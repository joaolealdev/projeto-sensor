Sensores simulados de temperatura, umidade e radiação solar mandam leituras para gateways que ficam perto do campo (a camada Edge). Um serviço separado calcula as médias e o gateway guarda o resultado. A v2 já faz a parte Edge e a Fog do diagrama do professor, e falta a detecção de anomalias.

01 Como funciona

Nó de campo → gateway → serviço de cálculo

Cada parte é um programa separado e elas só conversam pela rede, de dois jeitos:

  • do nó para o gateway: socket TCP, com uma mensagem JSON por linha;
  • do gateway para o serviço de cálculo: gRPC. O gateway chama Average() como se a função fosse local.

Arquitetura da v2

socket TCP · JSON por linha gRPC · contrato em proto/calc.proto ainda não existe

Caminho de uma leitura

  1. O nó fica escutando na sua porta e, a cada 1,5 s, gera uma leitura de clima simulado (um “dia” dura 2 minutos, e cada talhão tem o seu perfil de temperatura, umidade e sol) e manda para o gateway conectado, numa mensagem READING. Cada nó atende um gateway por vez, e um segundo que tente entrar recebe ERROR.
  2. O gateway é quem liga para os nós. Se um nó cai ou ainda não subiu, ele tenta de novo esperando 1 s, 2 s, 4 s… até 15 s.
  3. As leituras ficam separadas por nó. Quando um nó junta 6, o lote fecha.
  4. O gateway chama Average() no serviço de cálculo por gRPC, mandando uma série para cada medida e esperando no máximo 5 s.
  5. O serviço de cálculo valida o pedido, calcula a média de cada série e responde. Ele não guarda nada entre uma chamada e outra.
  6. O gateway grava no SQLite o nó, o período, quantas leituras entraram e as três médias (°C, % e W/m²). As leituras individuais não são guardadas.
  7. A Fog liga nos gateways e, a cada 5 s, pergunta pelas médias gravadas depois da última linha que ela já tem (ASK). O gateway responde com até 200 linhas (AVERAGES).
  8. A Fog grava tudo no fog.sqlite. Uma média que já estava lá é ignorada, então perguntar duas vezes não duplica nada.

Se o serviço de cálculo estiver fora do ar, o lote é descartado e vai para o log. O gateway continua recebendo leituras e volta a gravar quando o serviço voltar. Se a Fog cair, os gateways não são afetados e ela busca o que perdeu quando voltar.

02 Como os arquivos se comunicam

Quatro pastas, quatro processos

As pastas config e shared têm o que os quatro usam, e launcher só tem o menu que sobe os processos. Os import só dividem código; quando o sistema roda, a conversa é toda pela rede.

ArquivoPapelFala com
config/topology.tsDefine nós (com o perfil de cada talhão), gateways, portas e temposImportado por todos
field-node/node-server.tsPrograma do nó de campo (servidor TCP)Usa climate.ts; envia por socket ao node-link.ts
field-node/climate.tsGera o clima simulado (senoide do dia, ajustada pelo perfil do talhão)Chamado pelo node-server.ts
edge/gateway.tsPrograma do gateway; separa por nó e fecha os lotesUsa node-link.ts, calc-client.ts e store.ts
edge/node-link.tsConexão e reconexão com cada nóRecebe do node-server.ts
edge/calc-client.tsCliente gRPC (uma ligação reaproveitada)Chama o calc-service.ts
edge/store.tsGrava as médias no SQLite do gateway e devolve as que a Fog pedeLido depois pelo edge/report.ts
edge/fog-server.tsPorta do gateway para a Fog; responde ASK com AVERAGESUsa store.ts; atende o fog/gateway-link.ts
fog/fog.tsPrograma da Fog; junta as médias dos gatewaysUsa gateway-link.ts e fog-store.ts
fog/gateway-link.tsConexão, pergunta e reconexão com cada gatewayPergunta ao edge/fog-server.ts
fog/fog-store.tsGrava as médias de todos os gateways no fog.sqliteLido pelo edge/report.ts
launcher/menu.tsMenu que sobe e derruba os processosRoda os outros programas, sem entrar na conversa deles
calc-service/calc-service.tsServidor gRPC; calcula a médiaResponde ao calc-client.ts
proto/calc.proto + shared/calc-rpc.tsContrato do gRPC e seu carregamentoUsados pelo cliente e pelo servidor
shared/messages.ts + shared/wire.tsContrato do socket e leitura de JSON por linhaUsados pelo nó, pelo gateway e pela Fog

Na raiz do repositório ficam duas pastas: v1/, a primeira versão (o gateway pergunta ao sensor a cada 2 s e as médias vão para um JSON, com painel web), e v2/, a atual (o nó manda sozinho, o cálculo é por gRPC, a gravação é em SQLite e a Fog junta as médias dos gateways).

Outros pontos

  • Os tipos conferem: o npm run typecheck passa sem erros.
  • O npm run dev:menu sobe o cálculo, os nós, os gateways e a Fog no mesmo terminal.
  • Documentação: README na raiz, em v1/ e em v2/, e o COMO-FUNCIONA.md com a explicação do código.
  • A v1 está completa. O painel web dela só existe compilado (v1/dist e v1/web), sem o código-fonte em TypeScript.

04 O que falta

Ordem sugerida

  1. Criar o microsserviço de anomalias (outro .proto, no mesmo padrão do cálculo) e ligar na Fog por RPC.
  2. Fazer a Fog usar a resposta para o gatilho “umidade baixa? ligar irrigação”.
